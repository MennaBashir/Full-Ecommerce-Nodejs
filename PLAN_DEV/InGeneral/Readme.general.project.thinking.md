# 🧭 دليل التفكير في أي مشروع Backend

> مرجع بترجعي له **قبل ما تكتبي أول سطر كود** في أي مشروع، صغير أو كبير.
> الفكرة: المشروع الكبير هو مجموعة مشاريع صغيرة مترتبة صح.

---

## 0) القاعدة الذهبية

1. **افهمي قبل ما تكتبي.** ساعة تفكير توفر أسبوع إعادة كتابة.
2. **ابني أصغر نسخة شغالة (MVP) الأول**، وبعدين كبّري.
3. **كل مرحلة تتجرب بالكامل** قبل ما تنتقلي للي بعدها.
4. **اكتبي على الورق أو في ملف markdown أو Notion أو Excalidraw الأول:** المشكلة، الـ models، الـ endpoints.

---

## 1) افهمي المشروع (قبل أي تقنية)

جاوبي على الأسئلة دي كتابةً:

- المشروع بيحل **إيه مشكلة**؟ (جملة واحدة)
- مين **المستخدمين**؟ (زائر، عميل، أدمن، بائع...)
- كل نوع مستخدم **بيعمل إيه**؟ (اكتبيها كـ user stories)

```
بصفتي [نوع المستخدم] عايز [أعمل إيه] عشان [الفايدة]
مثال: بصفتي عميل عايز أضيف منتج للكارت عشان أشتريه بعدين
```

---

## 2) حدّدي الـ Scope (MVP)

قسّمي كل الـ features لتلات قوائم:

| القائمة | المعنى |
|---|---|
| ✅ **Must** | من غيرها المشروع مش شغال |
| 🟡 **Should** | مهمة بس ممكن تتأجل |
| ⏳ **Later** | إضافات لما كل حاجة تخلص |

**اسألي نفسك:** لو سلّمت المشروع بالـ Must بس، هل بيشتغل من البداية للنهاية؟ لو لأ، ناقص منه حاجة.

---

## 3) استخرجي الـ Models (الأسماء)

اقري الـ user stories وحطي خط تحت **الأسماء**: كل اسم مرشح يبقى model.

```
"العميل يضيف منتج للكارت ويعمل أوردر ويدفع"
 ← User, Product, Cart, Order, Payment
```

لكل model حدّدي:
- الـ fields الأساسية.
- أنهي fields **required** وأنهي **unique**.
- أنهي fields هتبحثي أو تفلتري بيها كتير ← **index**.
- لو الـ model عنده name بيظهر في URL ← أضيفي `slug` field (باستخدام `slugify`).

---

## 4) حدّدي العلاقات

لكل اتنين models اسألي:

| السؤال | النتيجة |
|---|---|
| A الواحد يخص كام B؟ وB الواحد يخص كام A؟ | واحد-لواحد / واحد-لكتير / كتير-لكتير |

### Embed ولا Reference؟

**Embed** (جوه نفس الـ document) لو:
- بتتقري دايماً مع الأب.
- عددها **محدود وصغير**.
- مش بتتعدل لوحدها.

**Reference** (`ObjectId` + `populate`) لو:
- عددها **بيكبر بلا حد**.
- بتتستخدم في أكتر من مكان.
- بتتعدل أو بتتقري لوحدها.

> ⚠️ متحطيش array بيكبر بلا حد جوه document (reviews، orders، notifications).

### Snapshot
لو الداتا لازم تفضل زي ما كانت وقت حدث معين (سعر وقت الشراء، عنوان الشحن)، **انسخيها** ومتعمليش reference بس.

---

## 5) صمّمي الـ API على الورق

لكل resource اكتبي الـ routes على الورق أو في ملف markdown:

```
GET    /resources          ← كل العناصر (+ filter, pagination)
GET    /resources/:id
POST   /resources
PATCH  /resources/:id
DELETE /resources/:id
```

- لو resource تابع لواحد تاني ← **nested**: `/products/:id/variants`.
- لكل route اكتبي: **مين يقدر يستخدمه؟** (public / user / admin).
- حدّدي شكل الـ response والـ errors مرة واحدة وثبّتيه.
- استخدمي versioning: `/api/v1/resources` — عشان لو غيّرتي حاجة في المستقبل.

---
## 6) فكري في منطق الـ Controller (من الـ Route)
 
الـ route بيحدد **إيه المطلوب**، والـ controller هو **إزاي ننفذه**.
 
### الـ route بيقولك إيه من غير ما تدري؟
 
```
POST /orders    (customer)
```
 
- **العملية:** إنشاء أوردر.
- **مين يقدر:** customer ← محتاج auth middleware.
- **المدخلات:** من `req.body` و `req.user` و `req.params` و `req.query`.
### جاوبي على الأسئلة دي لكل endpoint بالترتيب
 
| السؤال | مثال لـ `POST /orders` |
|---|---|
| **1) إيه المدخلات؟** | `req.user.id`، `req.body.addressId`، `req.body.couponCode` |
| **2) إيه اللي لازم يتحقق منه؟** | الكارت مش فاضي، المخزون كفاية، الكوبون صالح |
| **3) إيه الخطوات بالترتيب؟** | اقري الكارت ← snapshot ← احسبي الإجمالي ← transaction |
| **4) إيه الحالات الغلط؟ وكل واحدة ترجع إيه؟** | كارت فاضي ← 400، منتج مش موجود ← 404 |
| **5) إيه الـ response في النجاح؟** | `201` + الأوردر |

## 6) جهّزي هيكل المشروع

```
project/
├── config/        ← DB connection, env (.env هنا)
├── models/        ← Mongoose schemas
├── controllers/   ← منطق كل route
├── routes/        ← تعريف الـ endpoints
├── middlewares/   ← auth, validation, error handler
├── utils/         ← دوال مساعدة (AppError, slugify...)
├── .gitignore
└── app.js
```

جهّزي من البداية:
- [ ] `.env` و `.gitignore`
- [ ] اتصال الـ DB
- [ ] Error handling موحد (middleware واحد في الآخر)
- [ ] Validation للـ input (Joi أو Zod)
- [ ] Git repo ومن أول commit

## 7) رتّبي البناء حسب الاعتماد

الحاجة اللي غيرها محتاجها تتبني الأول:

```
Auth  ←  الـ resources المستقلة  ←  الـ resources المعتمدة  ←  العمليات المركبة
```

لكل مرحلة:
1. الـ model.
2. الـ controller والـ route.
3. الـ validation.
4. **جرّبي بـ Postman / Thunder Client** كل الحالات (نجاح + أخطاء).
5. commit.

---

## 8) حاجات بتتنسى (فكري فيها بدري)

| الموضوع | السؤال |
|---|---|
| **Authentication** | مين إنتي؟ (JWT، hashing بـ bcrypt) |
| **Authorization** | إيه المسموح لك؟ (roles) |
| **Pagination / Filter / Search** | الـ list اللي بتكبر لازم تتقسّم |
| **رفع الملفات** | هتخزني الصور فين؟ (Cloudinary / S3) |
| **Security** | `helmet`, `cors`, rate limiting, sanitize input |
| **Transactions** | عملية فيها أكتر من خطوة لازم كلها تنجح أو ولا واحدة |
| **Soft delete** | بدل المسح الحقيقي لو الداتا مرتبطة بحاجات تانية |
| **Indexes** | على الـ fields اللي بتبحثي بيها |
| **Logging** | تعرفي إيه اللي حصل لما حاجة تقع |
